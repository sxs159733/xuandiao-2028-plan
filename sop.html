每轮执行 Step 0—9

计划第 7 节的完整流程。Step 0 的备份必须先于任何写入；Step 5 用分段替换脚本而不是 sed，便于控制与校验。

0

备份

1

读记忆，定检索窗口

读跨轮 memory.md 的「执行记录」末条，取上次执行日期；窗口 = 次日起至今天。首次运行取近 3 天。同时读「遗留待确认项」与「下次执行建议」。

2

按优先级检索

广东 2027 定向选调公告（最高优先，未发布也要明确写「截至今日仍未发布」）→ 湖南 2027 选调后续与湖南省考节奏 → 湖大就业网通知公告栏新转载 → 国考 / 广东省考 / 江苏省考节点与实况 → 其他面向湖大的新定向公告。每条线索记录来源 URL、发布日、是否官方、原文关键句。

3

官方源核实

抓官方公告原文；附件 PDF 走下载 + 文本提取逐条匹配校名 / 专业代码 / 省份。对每个新公告回答：湖大在不在名单内？软条件能否用奖学金满足？专业目录怎么认？报名 / 缴费 / 笔试三个日期分别是什么？

4

形成判断，不堆数据

每条信息归类为「新增可报 / 条件收紧 / 时间风险 / 仅观察样本」，写出对应动作；检查是否推翻既有口径，若是写好「此前 X 作废」的句子。

5

重写 00 节

按第 5.4 节模板整节重写「00 今日动态」，起点 <section id="today">，终点锚点 <!-- ============ 1.；用 Python 分段替换。

6

同步 01—10 节 + hero + footer

按第 5.5 节映射逐项改；改完搜旧数值（被替代的竞争比、旧周期表述），确保没有自相矛盾的残留；合法保留的旧值必须带「已作废」标注。

7

校验

标签配对、\ufffd 乱码计数为 0、hero「最近更新」= 00 节标题日期 = 当日、11 个 section id 与 11 个 nav 锚点齐全、抽 00 节纯文本预览、文件末尾 </html> 完整。

8

写记忆

追加到跨轮 memory.md 的「执行记录」末尾；新建 / 追加当日 YYYY-MM-DD.md；清理本轮临时脚本，只留交付物。

9

交付

给出 HTML 路径；回复正文按第 10 节手机微信格式；若平台支持自动化结果回传，同时发送摘要。

交付前校验清单

计划第 8 节，逐条打勾再交付。

  • .bak.html 是上一版，未被本轮覆盖成新内容。
  • 00 节标题日期、hero「最近更新」、记忆文件日期三者一致。
  • 所有倒计时以当天为基准重算，标注「推算」。
  • 新出现的省份已同步到 03 / 04 / 07 / 10 节与 footer。
  • 新日期已进 08 时间轴 + 09 行动清单。
  • 被推翻的旧口径在 00 节显式声明作废，全文无矛盾残留。
  • 用户不能报的 2027 届批次没有写成行动建议。
  • 每个数字都有来源，机构数据标注「非官方」。
  • section / div / table 标签配对、\ufffd 乱码计数、结尾 </html>。
  • 回复正文符合手机微信格式。
07

记忆规范与回复格式

跨轮 memory.md（追加，永不覆盖）

第 9 节

结构固定的六段：任务定义 / 关键口径（已确认）/ 执行记录 / 遗留待确认项 / 下次执行建议。每条执行记录格式：### YYYY-MM-DD（第 N 轮，增量更新 · 本轮主题），含改动范围、关键新发现、核实数据、倒计时、备份说明。

当日日志 YYYY-MM-DD.md：交付物体积、改动范围、关键结论、技术要点、待办。只记有跨会话价值的内容，不记临时路径与工具报错。

回复用户的格式（手机微信阅读）

第 10 节
  • 不要宽表格：手机放不下 4 列以上，宁可拆成分块列表。
  • 每行短，一行一个信息点；金额与比率保留两位小数。
  • 结论前置：第一屏先给「多出几条路 / 哪条被卡死 / 哪个日期最危险」。
  • 重要数字单独成行、加粗；少用 Markdown 标题层级。
  • 长明细放文件里给路径，正文只留 5—8 条要点。
